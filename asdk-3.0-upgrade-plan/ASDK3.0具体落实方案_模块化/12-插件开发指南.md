# ASDK 3.0 插件开发指南

## 1. 开发边界

插件只通过 ASDK 3.0 C ABI 与 `asdk_host_api_v3` 使用平台能力。插件不得依赖、链接或调用：

- `asdkd` 内部实现、文件状态存储、systemd D-Bus、Portal；
- 其他插件的内存对象、线程对象或私有 socket；
- Runtime、Fast DDS 或 SHM 的私有实现类型；
- 未经 Host API 登记的长期线程、FD、mmap、设备句柄或 vendor handle。

插件的唯一导出符号：

```c
ASDK_ABI_EXPORT
const asdk_plugin_descriptor_v3* asdk_get_plugin_descriptor_v3(void);
```

除该符号外，不导出生命周期或业务入口作为 ASDK 运行时调用接口。

## 2. 插件目录

```text
plugins/<plugin-name>/
├── CMakeLists.txt
├── manifest.json
├── include/
│   └── <plugin-name>/
├── src/
│   ├── plugin_entry.c
│   ├── plugin_instance.cpp
│   └── plugin_instance.hpp
├── config.schema.json
└── tests/
```

发布物：

```text
<plugin-name>.so
manifest.json
config.schema.json
消息类型 Manifest 与 TypeSupport（如使用 DDS）
```

## 3. Manifest

```json
{
  "plugin_type": "example.camera",
  "abi_version": 3,
  "library": "libexample_camera.so",
  "build_id": "git-sha-or-semver",
  "supported_execution_modes": ["process"],
  "capabilities": ["TASK_API", "DDS_API", "SHM_PUBLISH", "RESOURCE_ADOPT"],
  "config_schema": "config.schema.json",
  "message_types": []
}
```

规则：

- `plugin_type` 在部署范围内唯一；
- `abi_version` 必须为 3；
- `library`、Schema、消息类型包路径必须位于受允许的插件前缀内；
- Manifest 声明能力必须与插件实际调用的 Host API 一致；
- 线程模式必须额外声明 `THREAD_MODE_SAFE`，并通过线程模式准入检查。

## 4. 执行模式

```json
{
  "id": "camera",
  "execution": { "mode": "process" }
}
```

| 模式 | 执行位置 | 故障边界 | daemon 重启后 |
|---|---|---|---|
| `process` | 独占插件 host 进程 | 单插件进程 | host 保持运行；新 daemon 接管 |
| `thread` | 显式配置的线程组 host 进程 | 整个线程组 | 线程组 host 保持运行；新 daemon 接管 |

线程模式禁止：

- 安装 signal handler；
- 调用 `fork()`；
- 修改 `cwd`、`umask`、locale 或环境变量；
- 创建 detached 长期线程；
- 使用未登记的全局设备/库状态；
- 以进程崩溃隔离作为错误恢复机制。

## 5. 生命周期

```text
UNLOADED
→ load + create
→ LOADED
→ initialize
→ INITIALIZED
→ start + ready
→ RUNNING
→ request_stop
→ STOPPED
→ deinitialize
→ LOADED
→ destroy + dlclose
→ UNLOADED
```

生命周期职责：

| 回调 | 插件职责 |
|---|---|
| `create` | 创建实例；保存 Host API；不启动任务、DDS 或 SHM |
| `initialize` | 解析不可变配置；声明逻辑端点和 SHM 通道；登记外部资源 |
| `start` | 创建受控任务；启动业务；在完成可服务条件后报告 ready |
| `request_stop` | 幂等请求停止；通知所有任务退出；不得无限阻塞 |
| `deinitialize` | 释放插件层业务资源；不得保留 Host API 对象 |
| `health` | 快速返回健康摘要；不得执行阻塞 I/O |
| `destroy` | 销毁实例私有内存；不得访问已释放 Runtime 资源 |

`start()`、`request_stop()`、`deinitialize()` 失败时，Runtime 负责后续清理顺序；插件必须返回稳定错误码，并通过 Error API 上报结构化根因。

## 6. 最小插件骨架

```c
typedef struct example_plugin {
    const asdk_host_api_v3* host;
    asdk_task_id worker_task;
    int initialized;
} example_plugin;

static asdk_status_code create(
    const asdk_host_api_v3* host,
    asdk_plugin_handle* out_handle) {
    example_plugin* self = calloc(1, sizeof(*self));
    if (self == NULL) return ASDK_RESOURCE_EXHAUSTED;
    self->host = host;
    *out_handle = self;
    return ASDK_OK;
}

static asdk_status_code initialize(
    asdk_plugin_handle handle,
    asdk_bytes_view config) {
    example_plugin* self = (example_plugin*)handle;
    /* 解析 config；声明 DDS/SHM；登记外部资源。 */
    self->initialized = 1;
    return ASDK_OK;
}

static asdk_status_code start(asdk_plugin_handle handle) {
    example_plugin* self = (example_plugin*)handle;
    if (!self->initialized) return ASDK_INVALID_STATE;
    /* 仅通过 Task API 创建可停止、可 join 的任务。 */
    return ASDK_OK;
}

static asdk_status_code request_stop(asdk_plugin_handle handle) {
    example_plugin* self = (example_plugin*)handle;
    /* 幂等通知任务停止；不 join、不 sleep 到超时。 */
    return ASDK_OK;
}

static void destroy(asdk_plugin_handle handle) {
    free(handle);
}
```

实际代码必须使用项目冻结的 ABI 头文件、状态码和 Host API 调用签名；本骨架只描述生命周期责任。

## 7. Task 规则

- 所有长期业务任务必须由 Task API 创建；
- 任务循环必须频繁检查 stop token；
- 不创建 detached 线程；
- 所有 C++ 异常必须在插件边界内捕获并转换为错误码；
- `request_stop()` 只发出停止请求；等待与超时处理由 Runtime 执行；
- 任务退出、异常和 ready 状态必须通过 Host API 报告。

## 8. DDS 规则

- 在 `initialize()` 仅声明逻辑 reader/writer；Runtime 在 `start()` 创建物理 DDS 端点；
- 插件公共头、ABI struct 和跨边界接口不得出现 Fast DDS C++ 类型；
- 小数据使用 DDS serialized payload；
- 不阻塞 Fast DDS listener 线程；回调由 Runtime 有界队列与回调执行器调度；
- `stop()` 返回后不得再向插件交付旧 callback epoch 的数据；
- 发布前检查 Writer、类型、QoS、状态和 payload 限制。

## 9. SHM 规则

- 在 `initialize()` 声明 SHM 通道；
- 在 `RUNNING` 后通过 Host API 执行 allocate、seal、acquire、release；
- 大 payload 不写入 DDS payload，只发布 `LargeDataHeader`；
- acquire 得到的 `SharedSample` 必须在最短作用域内 release；
- 不缓存失效 block、offset、capability 或旧 epoch；
- pool 满时仅执行配置的背压策略，不覆盖已发布数据。

## 10. 资源、日志与错误

### 资源登记

插件创建或接管的长期资源必须登记：

```text
FD / socket / timerfd
mmap
设备句柄
vendor SDK handle
任务与回调资源
```

每个资源必须声明清理回调、所属资源域和销毁顺序。未登记资源视为插件违规。

### 日志

只使用 Host Log API。Runtime 自动绑定：

```text
ASDK_HOST_ID
ASDK_PLUGIN_ID
ASDK_OPERATION_ID
ASDK_CONFIG_GENERATION
ASDK_STATE_GENERATION
ASDK_MONOTONIC_NS
```

禁止记录密钥、token、设备凭据或完整二进制 payload。

### 错误

生命周期函数返回稳定 `asdk_status_code`；详细错误通过 Error API 上报：

```text
错误码
模块
插件 ID
阶段
消息
单调时间
```

不得通过解析错误文本实现控制逻辑。

## 11. Health

`health()` 必须快速、无阻塞、无副作用。建议只检查：

- 任务是否异常退出；
- DDS 端点匹配与队列溢出状态；
- SHM lease、背压与协议错误；
- 设备句柄与最近业务成功时间；
- 已登记资源是否超出预算。

健康状态：

```text
HEALTHY   正常运行
DEGRADED  可继续运行但存在降级条件
FAILED    不可恢复故障，等待 Host/Runtime 上报
```

## 12. 构建与 ABI 检查

```text
1. 以 C11 ABI 头文件编译插件入口。
2. 以 C++17 编译插件内部实现。
3. 仅导出 asdk_get_plugin_descriptor_v3。
4. 检查 descriptor 的 abi_version、struct_size 和所有必填函数指针。
5. 禁止插件 ABI 依赖 STL、RTTI、C++ 异常、虚函数对象和编译器相关布局。
6. 运行 asdk-plugin-inspect 检查 Manifest、ELF、ABI 与消息类型包。
```

## 13. 插件验收清单

- [ ] Manifest、Schema、动态库和消息类型包校验通过。
- [ ] process/thread 模式与 Manifest 声明一致。
- [ ] `create → initialize → start → stop → deinitialize → destroy` 全链路通过。
- [ ] start、stop、health、任务异常、回调排空和资源清理均有测试。
- [ ] daemon 断开期间插件继续按当前状态运行；重连后可由快照接管。
- [ ] 插件崩溃只扩大到其执行模式允许的故障边界。
- [ ] DDS、SHM、FD、线程、lease 在重复 start/stop 后无永久增长。
- [ ] 不存在未登记资源、detached 线程、跨 ABI C++ 对象或敏感日志。
