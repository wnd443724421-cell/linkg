# 5G 射频强发诊断

生产与研发使用正式固件的 Web 诊断入口，不开启 SSH。正常 Cellular FSM 不参与射频测试。Network Manager 确认原 Owner join、stop、deinit 后创建独立任务，任务独占 /dev/ttyUSB1。测试结束关闭强发、退出 FTM、查询 mode=0 并释放 AT Channel；原配置开启时恢复 Owner，关闭时保持关闭。不修改用户配置。

## 使用及安全
- 仅在受控传导测试环境使用，先连接正确发射端口、50 Ω 测试通路、衰减器和仪表；禁止开放环境强发。
- Web 需要明确确认；该确认并非访问控制。现有 CGI 的外部请求来源、授权和生产网络隔离仍须在正式发布前确认。后端监听 loopback 不等于 CGI 仅允许本地以太网。
- 选 LTE/NR5G、频段、带宽、中心频率、时长。后端以整数 kHz 校验并对齐栅格；实际信道与标称中心频率只读。
- TX_power 固定为文档推荐值 23，不是保证的实测功率。AT OK 不等于功率合格。
- 频段与带宽表是待验证的候选配置，FTM 文档并未给出 RG255AA 各子型号支持组合、实际功率和允许误差；必须实板确认。
- 进入 FTM 前同步写入 /app/.linkg-rf-pending，同时兼容旧版 /tmp/linkg-rf-pending。启动时由独立线程确认退出 FTM 并释放 AT 通道，再移除标记并允许正常蜂窝 Owner 启动。射频清理失败后再次点击开始只请求恢复，本次不发送强发启动命令。整机掉电、USB 失联和模组不响应仍需板端验证，失去 AT 控制时需依靠测试台断电能力。
- 本次未修改正常蜂窝 FSM、持久化配置或内核驱动。

- RF-TEST 日志记录 QRFTEST 原始响应、耗时与阶段。Web 分别报告测试控制、清理以及正常蜂窝恢复结果。

## 验收
1. 编译 x86 和 ARM，检查 Web 资源在烧录和升级包中一致。
2. 出厂关闭蜂窝、无 SIM 的状态下启动 n41/n78 等经厂家确认的频段，检查实际信号和频率。
3. 开启蜂窝后执行测试，确认正常 Owner 退出、AT 独占、结束恢复；检查原配置不变。
4. 手动停止、到期、重复提交、页面关闭、拔网线、AT 超时、USB 拔出、应用退出、应用被杀、整机重启。
5. 测试期间并发修改蜂窝配置、配置导入、重启、升级、其他诊断；检查拒绝策略与恢复。
6. 确认 FTM 退出失败不会启动正常 Owner，并验证异常清理/模组电源恢复。
7. 由厂家提供各频段的合格功率范围与仪表参数后制定生产判定标准。当前页面只报告控制结果。
