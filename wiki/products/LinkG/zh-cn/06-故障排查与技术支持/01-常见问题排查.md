# 常见问题排查

先确定故障发生在哪一段。依次验证**本地网口 → 本机 LinkG → 对端 LinkG → 业务设备**。能打开对端 Web 后，再检查业务服务的地址、端口和回程。

| 现象 | 排查入口 |
|---|---|
| 网口未连接，或电脑获取不到 IP | [检查本地以太网和 DHCP](#1-网口不通或获取不到-ip) |
| 能打开本机 Web，访问不了对端 LinkG | [检查电脑路由和组网](#2-能打开本机-web访问不了对端-linkg) |
| 对端 LinkG 可达，接在它网口上的设备不通 | [检查目标地址、端口和回程](#3-对端-linkg-可达但业务设备不通) |
| 视频卡顿、数传中断或业务频繁切换 | [检查该业务实际使用的链路](#4-业务卡顿或频繁切换) |
| 升级中断线，或升级后打不开 Web | [检查升级阶段和设备访问地址](#5-升级后访问异常) |

## 1. 网口不通或获取不到 IP

1. 确认 LinkG 已供电、网线两端插紧、电脑网卡已启用。若电脑提示“网络电缆被拔出”或 Linux 显示 `NO-CARRIER`，先更换已知正常的网线或交换机端口，确认网口显示已连接。
2. 网口已连通时，检查电脑连接 LinkG 的网卡是否设为自动获取 IPv4 地址，重新获取 DHCP 租约。能从其他地址打开 LinkG Web 时，进入 **网络配置 → 基础网络** 检查 DHCP 服务是否开启。同一个以太网内有多台 DHCP 服务器时，核对电脑的租约来自哪台设备。
3. 已知 LinkG 接入网段时，可临时给电脑设置同一网段内未占用的 IP，再打开 LinkG 的接入地址。例如接入 IP 为 `192.168.1.1/24` 时，使用该地址进入管理页。静态地址和续租命令见[基础网络](../03-功能与配置指南/03-网络配置/01-基础网络.md)。

电脑在该网口取得预期地址并能打开本机 Web 后，再验证组网路由。

## 2. 能打开本机 Web，访问不了对端 LinkG

1. **用对端组网 IP 访问。** 例如组网网段为 `172.28.0.0/16`，节点 2 的组网 IP 为 `172.28.2.1`。
2. **检查电脑的组网路由。** 到组网网段的下一跳应为本地 LinkG 的接入 IP。DHCP 续租后仍缺少这条路由时，按[基础网络](../03-功能与配置指南/03-网络配置/01-基础网络.md)手动添加。电脑可以沿用原有 Internet 默认网关。
3. **到两端的“概览”查看“组网节点”。** 核对节点 ID 唯一、组网网段一致，确认表中能看到对端及所需的 Wi-Fi 或蜂窝路径。对端未出现时，按[一对一配置](../02-快速入门/01-一对一配置.md)检查 AP／STA 角色和所用链路。

恢复后，从电脑按对端组网 IP 打开 Web，再验证实际业务。[概览与路径状态](../03-功能与配置指南/01-概览/01-概览.md)

## 3. 对端 LinkG 可达，但业务设备不通

依次检查**目标地址、服务端口和回程路由**。以下用节点 2 网口连接的雄迈摄像头举例。

| 检查项 | 怎样确认 |
|---|---|
| 对端以太网 | 检查摄像头供电、网口和 IPv4 地址。有条件时，先从摄像头所在以太网访问相同服务。 |
| 目标 IP | 节点 2 用 **NAT** 时，摄像头实际 IP 为 `192.168.1.10`，地面端使用组网映射地址 `172.28.2.10` 访问。节点 2 用**直连**时，摄像头设为 `172.28.2.10/24`，地面端访问它的实际 IP。 |
| 服务端口 | 核对程序实际监听的协议和端口。例如先测试摄像头 RTSP 的 TCP `554`，再用播放器验证实际画面。 |
| 回程路由 | **直连、SNAT 关闭**时，摄像头应经摄像头侧 LinkG 返回地面网段，例如将默认网关设为 `172.28.2.1`。摄像头无法配置有效回程时，可在**摄像头侧 LinkG**开启直连 SNAT，保存并重启服务后重新发起连接。 |

RTSP 端口能连但无画面时，核对账号、通道和编码。使用 RTP over UDP 时，同时确认协商的 UDP 媒体能到达播放器。[网络摄像头图传实测](../04-业务场景与应用案例/01-网络摄像头图传.md)

## 4. 业务卡顿或频繁切换

1. 记下受影响的业务、发生时间和当时的操作，例如开始拉流、增大码率或改变链路环境。
2. 在 **切换策略 → 运行状态** 查看该业务的主链路、备用链路、路径状态和更新时间。STA 侧可同时查看远端计划确认、Wi-Fi 业务探测和包缺口样本。结合故障前后的状态判断实际使用的路径。
3. 按应用实际使用的协议和端口核对[流量规则](../03-功能与配置指南/03-网络配置/02-流量规则.md)。需要单独检查链路吞吐或延时时，使用[链路性能测试](../03-功能与配置指南/06-诊断工具/02-链路性能测试.md)。

使用相同业务和负载复测，同时观察实际画面或数据以及发送计划。[运行状态字段说明](../03-功能与配置指南/05-切换策略/01-运行状态.md)

## 5. 升级后访问异常

1. 候选版本提交后设备会重启，Web 会暂时断开。处于安装、写入、验证或恢复阶段时，保持供电，等待当前操作结束。
2. 通过本地以太网重新访问，核对电脑 IPv4 地址和 LinkG 管理 IP。连通后回到 **系统管理 → 固件升级**，确认页面报告的升级结果。
3. 在 **设备配置 → 基础配置** 核对软件版本，并验证组网和正在使用的业务。若提示升级失败或已恢复稳定版本，保留页面提示、升级包文件名和当前版本，以便进一步定位。

完整流程见[固件升级](../03-功能与配置指南/07-系统管理/04-固件升级.md)。问题持续存在时，见[售后与技术支持](02-联系技术支持.md)。
